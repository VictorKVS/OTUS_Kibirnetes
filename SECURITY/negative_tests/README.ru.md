# FATHER Negative Testing & Threat Discovery — контур альтернативных сценариев

**Статус:** реализована только автономная офлайн-симуляция правил; реальные воздействия на Docker, Kubernetes и GitHub отсутствуют.

## Зачем
Одна и та же операция может быть полезной, бесполезной либо опасной в зависимости от контекста, прав, среды и состояния. Пример: «пересоздать Minikube» допускается после проверки учебной среды, но недопустимо как универсальное исправление ошибок Docker.

## Проверяемые классы
1. **Неверная цель:** команда для лаборатории случайно адресована production.
2. **Отсутствие разрешения:** пользователь или агент пытается изменить среду без согласования.
3. **Обход разрешённых операций:** запрос произвольной shell-команды вместо предусмотренной кнопки.
4. **Неудачное исправление:** повторить действия без проверки первопричины.
5. **Повтор и гонка:** дважды применить операцию, потерять идемпотентность.
6. **Сбой связи:** исполнитель не отвечает, сайт не должен сообщать «успешно».
7. **Ложный негатив:** сканер пропустил угрозу — нужен второй независимый контроль.
8. **Ложный позитив:** сканер обнаружил несуществующий риск — ручное подтверждение.
9. **Дрейф:** текущая конфигурация отличается от версии Git, политики или плана.
10. **Неполные доказательства:** исправление выполнено, но отсутствует тест результата.

## Запуск офлайн-теста
```powershell
python SECURITY/negative_tests/guardrail_simulator.py
```
В результате выводится JSON с ожидаемыми и фактическими решениями. Скрипт **ничего не меняет** в системе и не является полноценной реализацией безопасности: настоящий исполнитель должен независимо проверять полномочия, путь, цель, параметры, подпись политик и факт утверждения.

## Матрица приёмки
**Угроза → альтернативный сценарий → ожидаемое решение → измерение → доказательство → разбор расхождений → исправление → повторный тест.**

Пропущенная угроза не исчезает после одного PASS. Метрики будущего модуля: покрытие контрольных сценариев, доля false negative/false positive, доля успешно воспроизведённых исправлений, риск регрессии, MTTD/MTTR, количество истёкших исключений, доля действий без доказательств.

## Подключение к фабрике (будущая работа)
Карточки сайта: «Что будет, если?», «Безопасная симуляция», «Негативные тесты», «Сравнить решения», «Найти слепые зоны», «Повторить проверку». Каждое испытание журналируется, но симуляция и реально выполненное действие всегда имеют разные статусы.

Интеграция через CI/PR, рискованные операции не запускаются автоматически. Фабрика должна учитывать российские нормативные требования по применимости, а не утверждать соответствие ФСТЭК по одному тесту.
