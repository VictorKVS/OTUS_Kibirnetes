# Контракт интеграции FATHER Factory с Kubernetes и DevSecOps

**Целевой проект:** `VictorKVS/OTUS-`, ветка `feature/otus-homework-site`, каталог `factory/`. Интеграция в интерфейс не доказывает, что backend подключён и работает.

## Источники данных
- Уроки: восемь каталогов `LESSONS/01_...` — `08_...`.
- Домашние задания: `DZ_01` и последующие.
- Угрозы: `SECURITY/threats/devsecops_top100.csv`.
- Аудитор: `SECURITY/agent/audit_k8s.py`.
- Нормативная карта: `SECURITY/regulations/RU_REGULATORY_MAP.md`.
- Базовый CI: `.github/workflows/security-ci.yml` (в PR).
- Допуск и доказательства: Pull Request, журналы и Evidence Store.

## Входы и выходы фабрики
**Вход:** номер урока, репозиторий и ссылка на версию, манифесты, область рисков, классификация системы и разрешения.

**Исполнители:** Алина (требования) → DevOps (реализация) совместно с DevSecOps (аудит) → QA → диспетчер FATHER.

**Выход:** цепочки «угроза → мера → тест → доказательство», JSON-отчёт, результаты PR, решение о релизе.

Автоматический Security Agent не имеет права самостоятельно разрешать активные испытания или выпуск в Production.

## Требования к сайту
- Видимый раздел Kubernetes и DevSecOps.
- Восемь уроков с привязкой к проверкам и контролям.
- Чёткие статусы «план», «каркас», «проверено на реальной системе».
- Использование публичных исходников из Git; запрет на публикацию ключей, учётных данных и персональных данных.
