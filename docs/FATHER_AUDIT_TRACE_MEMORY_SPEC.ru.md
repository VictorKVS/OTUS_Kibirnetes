# FATHER Engineering — спецификация аудита, знаний, трассировки и памяти, версия 0.1

**Статус:** проектная спецификация от 14.10.2026. Не внедрено и не сертифицировано.

## Основной контракт действий
Каждая кнопка запускает только заранее разрешённую операцию. Обязательные атрибуты: исполнитель, задача, проект, область действия, проверка параметров, политика согласования, ключ идемпотентности, время и ожидаемый результат. Произвольный ввод команд оболочки через браузер запрещён. Для высокорисковых изменений требуется подтверждение человека.

### Структура события
Технические имена полей сохраняются без перевода, чтобы не нарушать совместимость API.
```json
{
  "event_id":"UUIDv7","trace_id":"UUID","span_id":"UUID",
  "occurred_at":"2026-10-14T12:00:00+03:00",
  "project_id":"OTUS-K8S","lesson_id":"02","task_id":"DZ-01",
  "actor_type":"human|agent|runner","actor_id":"stable-id",
  "operation":"minikube.healthcheck","operation_version":"1.0",
  "target":"local:otus-k8s","scope":"read-only",
  "input_digest":"sha256:...","result":"failed","error_code":"GUEST_NOT_FOUND",
  "artifact_ids":["EV-..."],"parent_event_id":null,
  "approval_id":null,"policy_version":"sec-policy-1","record_schema_version":"1.0"
}
```
Не записывать пароли, токены, секреты, необработанные персональные данные и чувствительные промпты. Идентификаторы трассировки генерируются сервером; личность пользователя подтверждается серверной аутентификацией. Корреляция событий: интерфейс → API → оркестратор → исполнитель → Git/CI → Kubernetes.

## Разделение хранилищ
1. **Git:** исходный код и история изменений.
2. **Журнал разработки:** решения, ADR, риски, тесты, изменения, связи с commit и PR.
3. **Реестр исполнений (Execution Ledger):** добавляемые без изменения прошлого структурированные события; RBAC, контроль целостности, сроки хранения.
4. **Журнал аудита ИБ:** входы, авторизация, политики и действия администраторов; ограниченный доступ, внешняя передача.
5. **Реестр инцидентов:** расследования, первопричины, корректирующие меры, повторные тесты.
6. **База знаний/граф:** нормализованные проверенные утверждения со ссылками на источники, периодом действия, версиями, оценкой уверенности и рецензентами.
7. **Память агентов:** изменяемый и потенциально ошибочный контекст; **не является доказательным журналом**.
8. **Хранилище доказательств:** версионированные/неизменяемые артефакты, хеши, метаданные, политики доступа и хранения. SHA-256 при сверке с доверенным отдельно сохранённым хешем помогает выявить изменение, но не удостоверяет автора.

## Минимальный граф трассировки
Требование → Угроза → Контроль → Тест → Запуск → Доказательство → Находка → Исправление → PR → Сборка → Релиз → Развёртывание → Наблюдение.

Каждая связь содержит источник, исполнителя, время, версию политики и статус проверки. Неизвестные или непроверенные связи не получают статус PASS.

## Требования к интерфейсу
Для каждой операции показывать: что и зачем, затрагиваемые активы, полномочия, условия, угрозы и меры, ссылки на справку, режим «модель/реальное выполнение», класс риска, подтверждение, прогресс, фактический вывод, причину ошибки, безопасное исправление, откат и ссылки на журналы. Серверная аутентификация и авторизация обязательны. Нужны тайм-ауты, ограничение конкурентности и частоты, защита CSRF (где применимо), сетевая изоляция, структурированные логи и correlation ID. Успех нельзя показывать до подтверждения backend.

## Приёмочные тесты — предстоит реализовать
- Операция создаёт события трассировки, ссылку на источник и читаемый журнал, не раскрывая секреты.
- Недопустимая операция отклоняется и отказ журналируется.
- Изменение высокого риска блокируется без подтверждения человека.
- По trace_id находятся артефакты и проверяется их хеш.
- Повтор запроса не дублирует разрушительные операции.
- При недоступном исполнителе показывается ошибка или тайм-аут, а не фиктивный успех.
- Проверяются RBAC, сроки хранения, безопасная реакция на сбой записи аудита.
- Формируется аудиторское досье с областью действия, требованиями, доказательствами, ответственными, тестами и исключениями.
- Проверяются резервное копирование и восстановление метаданных журналов и доказательств.
